### L. 狀態圖建模對象選擇

| 問題 | 回答 |
| --- | --- |
| 建模類別 | ActivityApplication（活動申請） |
| 為什麼具有重要生命週期 | 待審核、補件、核准或退回會影響可執行操作與角色可見結果；實際狀態集合仍須依 FR-08 確認 |
| 不同狀態是否允許不同操作 | 是；待審核、待補件及審核結果在目前實作允許不同操作，但核准／補件／退回與終止語意仍列待確認 |
| 哪些規則限制狀態轉移 | BR-03 已確認有效新申請初始為待審核；補件原因、退回原因、終止狀態與撤銷規則尚待確認，不可自行補造 |
| 狀態錯誤會造成什麼風險 | 未確認即允許回轉會使場地與角色畫面不一致；若把暫時處理步驟當成實體狀態，也會讓資料與介面名稱不一致 |
| 對應需求與使用案例 | FR-05～FR-08、BR-03、UC-01、UC-03～UC-06、DFD 3.0／5.0、`ActivityApplication.status` |
