### L. 狀態圖建模對象選擇

| 問題                     | 回答                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 建模類別                 | ActivityApplication（活動申請）                                                                                          |
| 為什麼具有重要生命週期   | 申請從建立、待審核、補件重送到核准或退回會改變可執行操作、場地占用與角色可見結果；錯誤狀態會造成重複借用或未授權審核     |
| 不同狀態是否允許不同操作 | 是；待審核可核准／要求補件／退回，待補件可修改重送，已核准與已退回在本次模型中為終止狀態                                 |
| 哪些規則限制狀態轉移     | BR-03 規定有效新申請初始為待審核；補件／退回必須有原因；只有待補件可重送；有效且無衝突才能建立或重送                     |
| 狀態錯誤會造成什麼風險   | 已核准申請若被任意改回補件會讓已確認場地失效；已退回申請若直接重送會繞過重新申請規則；錯誤狀態也會讓角色畫面與通知不一致 |
| 對應需求與使用案例       | FR-05～FR-08、BR-03、UC-01、UC-03～UC-06、DFD 3.0／5.0、`ActivityApplication.status`                                   |

### N. 非法狀態轉移

| 目前狀態 | 嘗試事件             | 為何不允許                                                                         | 預期系統反應                                                                                       | 測試編號 |
| -------- | -------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- | -------- |
| 已核准   | 再改為待補件或已退回 | 已核准是本次模型的終止狀態，場地行程已對管理員與學生公開，不可繞過撤銷規則直接回轉 | 拒絕更新並保留已核准；目前 Java`updateStatus` 未檢查目前狀態，程式碼檢查顯示仍會接受，列為待修正 | IST-01   |
